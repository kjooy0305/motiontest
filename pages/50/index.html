🟩Node.js 완전 정복
🟩 Node.js — 그래서 왜 "노드"야?
이름이 신기한 이유가 있습니다. 네트워크 토폴로지에서 '노드(Node)'는 연결 지점을 뜻합니다. Node.js는 서버·클라이언트·피어를 잇는 네트워크의 각 연결 지점이 되는 런타임을 목표로 만들어졌습니다.
🌐이름의 유래 — "Node"가 뭔데?
Node = 네트워크의 점(點)
그래프·네트워크 이론에서 노드(node)는 엣지(edge, 간선)로 연결된 꼭짓점입니다. 인터넷을 생각하면 서버 한 대, 라우터 하나, 컴퓨터 한 대가 각각 노드입니다.
  • 창시자 라이언 달(Ryan Dahl)이 2009년 발표할 때 내건 개념 — "어떤 디바이스든 네트워크의 노드가 될 수 있도록 가볍고 이벤트 기반으로 만들자".
  • 당시 Node.js는 서버 측에서 JavaScript를 실행하는 첫 번째 실용적 환경이었습니다. 브라우저 안에만 갇혀 있던 JS가 서버·CLI·IoT·데스크톱 어디서든 쓸 수 있는 "네트워크 노드"가 됐다는 의미입니다.
  • ".js" 접미사는 JavaScript 런타임임을 명시하는 관례. 이후 수많은 프레임워크가 이 네이밍을 따랐습니다 (Vue.js, Next.js…).
한 줄 요약 — Node.js = "JavaScript로 동작하는 네트워크 노드(연결 지점)를 만드는 런타임"
⚙️Node.js가 뭔가요?
정의Chrome V8 엔진 위에서 동작하는 JavaScript 런타임. 브라우저 없이 서버·터미널에서 JS를 실행합니다.
출시2009년 5월, Ryan Dahl 발표. 2010년 npm 등장으로 생태계 폭발.
특징이벤트 기반 + 논블로킹 I/O + 싱글 스레드. 파일 읽기·네트워크 요청을 기다리는 동안 다른 작업을 처리합니다.
쓰임새웹 서버, REST API, CLI 도구, 실시간 채팅, IoT, 데스크톱 앱(Electron), 빌드 도구(Webpack, Vite) 등
V8이 뭔가Google이 만든 JavaScript 실행 엔진. Chrome 브라우저 안에도 같이 들어 있습니다. Node.js는 이 엔진을 꺼내 서버 환경에 끼워 넣은 것입니다.
🆚브라우저 JS vs Node.js — 뭐가 다른가
항목브라우저Node.js
실행 환경웹 페이지 안서버 / 터미널
DOM/window있음없음 (document·window 쓰면 에러)
파일 시스템접근 불가자유롭게 읽기·쓰기 (fs 모듈)

핵심 차이 — 브라우저 JS는 화면을 다루고, Node.js는 시스템을 다룹니다.
🚀5분 안에 첫 서버 띄우기
server.js
// Node.js 내장 http 모듈 — 설치 필요 없음
const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' });
  res.end('안녕, Node.js!\n');
});

server.listen(3000, () => {
  console.log('서버 실행 중 → http://localhost:3000');
});
실행
node server.js
브라우저에서 http://localhost:3000 열면 됩니다. npm 없이, 설치 없이, Node.js만으로 서버가 올라갑니다.

🧠 핵심 개념
Node.js를 처음 배울 때 가장 헷갈리는 세 가지 — 이벤트 루프, 논블로킹, 비동기를 먼저 잡으면 나머지가 따라옵니다.
🔄이벤트 루프 (Event Loop) — Node의 심장
한 줄 개념 — 싱글 스레드인데도 수천 개의 요청을 동시에 처리할 수 있는 이유. I/O 작업을 기다리는 동안 다른 콜백을 먼저 실행합니다.
콜 스택
→
Node API
(비동기 작업 위임)
→
태스크 큐
→
이벤트 루프
(큐 → 스택)
  • 콜 스택이 비면 이벤트 루프가 태스크 큐에서 다음 콜백을 꺼내 스택에 올립니다.
  • 파일 읽기·DB 쿼리·타이머 같은 느린 작업은 Node API(libuv)에 위임하고 메인 스레드는 곧바로 다음 코드를 실행합니다.
  • 작업이 끝나면 결과와 콜백이 큐에 들어오고, 루프가 스택에 올려줍니다.
이벤트 루프 동작 예시
console.log('1');            // 즉시 실행

setTimeout(() => {
  console.log('3');          // 0ms 후 → 사실 큐에서 기다림
}, 0);

console.log('2');            // 즉시 실행

// 출력: 1 → 2 → 3
// setTimeout 0이라도 콜 스택이 비운 후에 실행됩니다
🚫블로킹 vs 논블로킹
구분동작Node에서
블로킹작업이 끝날 때까지 다른 코드를 실행 못 함fs.readFileSync 같은 Sync 메서드
논블로킹작업을 위임하고 즉시 다음 코드로fs.readFile (콜백), Promise, async/await
서버 코드에서 Sync 메서드 금지
readFileSync를 서버 요청 핸들러 안에 쓰면 그 요청 처리 중 다른 모든 요청이 멈춥니다. 스크립트 초기화 시점에만 허용.
블로킹 vs 논블로킹 비교
const fs = require('fs');

// ❌ 블로킹 — 파일 읽는 동안 서버 전체 정지
const data = fs.readFileSync('file.txt', 'utf8');
console.log(data);

// ✅ 논블로킹 — 읽는 동안 다른 요청 처리 가능
fs.readFile('file.txt', 'utf8', (err, data) => {
  if (err) throw err;
  console.log(data);
});

// ✅ async/await — 가독성 좋은 현대적 방식
const { readFile } = require('fs/promises');
const text = await readFile('file.txt', 'utf8');
console.log(text);
📦모듈 시스템 — CommonJS vs ES Modules
항목CommonJS (CJS)ES Modules (ESM)
확장자.js / .cjs.mjs / .js(type:module)
불러오기require('모듈')import x from '모듈'
내보내기module.exports = ...export default ... / export {}
로드 시점동기 (런타임)정적 분석 (파싱 단계)
현황Node.js 기본값, 오래된 패키지 대부분브라우저·최신 패키지 표준. Node v22+에서 require(ESM) 지원 추가됨
두 방식 비교
// ── CommonJS (전통적) ──────────────────────
const path = require('path');
module.exports = { greet: () => 'hello' };

// ── ES Modules (현대적) ────────────────────
import path from 'path';
export const greet = () => 'hello';
// package.json에 "type": "module" 추가 필요
새 프로젝트는 ES Modules를 권장하지만, 기존 생태계(Express 등)는 아직 CommonJS가 많습니다. 혼용 시 에러 나기 쉬우니 한 프로젝트에서 하나만 사용하세요.
⚡비동기 3단계 진화 — 콜백 → Promise → async/await
같은 파일 읽기 — 3가지 방식
const fs = require('fs');
const { readFile } = require('fs/promises');

// 1️⃣ 콜백 (Node.js 전통 방식) — 깊어지면 "콜백 지옥"
fs.readFile('a.txt', 'utf8', (err, data) => {
  if (err) return console.error(err);
  fs.readFile('b.txt', 'utf8', (err2, data2) => {
    console.log(data + data2);   // 중첩이 깊어짐
  });
});

// 2️⃣ Promise — .then() 체인으로 평탄화
readFile('a.txt', 'utf8')
  .then(d1 => readFile('b.txt', 'utf8').then(d2 => d1 + d2))
  .then(console.log)
  .catch(console.error);

// 3️⃣ async/await — 동기 코드처럼 읽힘 (현재 권장)
async function main() {
  try {
    const [d1, d2] = await Promise.all([
      readFile('a.txt', 'utf8'),
      readFile('b.txt', 'utf8'),
    ]);
    console.log(d1 + d2);
  } catch (err) {
    console.error(err);
  }
}
main();
🧵Worker Threads — 진짜 멀티스레드가 필요할 때
  • Node.js는 메인 루프는 싱글 스레드지만, worker_threads 모듈로 실제 OS 스레드를 추가로 쓸 수 있습니다.
  • 이미지 변환·암호화·대용량 연산 등 CPU를 오래 점유하는 작업에만 씁니다.
  • 일반 I/O 비동기 처리에는 Worker가 필요 없습니다 — libuv 스레드풀이 알아서 처리합니다.
worker_threads 기본 예시
const { Worker, isMainThread, parentPort } = require('worker_threads');

if (isMainThread) {
  // 메인 스레드
  const worker = new Worker(__filename);
  worker.on('message', msg => console.log('결과:', msg));
} else {
  // 워커 스레드 — 무거운 계산
  let sum = 0;
  for (let i = 0; i < 1e9; i++) sum += i;
  parentPort.postMessage(sum);
}
🌍전역 객체와 특수 변수
이름설명
__filename현재 파일의 절대 경로 문자열
__dirname현재 파일이 있는 디렉터리의 절대 경로
process현재 Node 프로세스 정보 + 제어. process.env, process.argv, process.exit()
process.env환경 변수 객체. process.env.PORT, process.env.NODE_ENV
process.argv커맨드라인 인수 배열. node app.js hello → argv[2] = 'hello'
global브라우저의 window에 해당하는 전역 객체
Buffer이진 데이터 처리. 파일·네트워크 스트림에서 자주 사용
ESM(import) 방식에서는 __filename, __dirname이 없습니다. 대신 import.meta.url과 fileURLToPath를 조합해 씁니다.
📦 내장 모듈 (Built-in Modules)
Node.js에 기본으로 내장된 모듈들 — 설치 없이 require()만으로 바로 사용가능합니다. 자주 쓰는 것 위주로 정리했습니다.
📁fs — 파일 시스템
fs 기본 사용법
const fs = require('fs');
const { readFile, writeFile, mkdir } = require('fs/promises');

// 읽기
const text = await readFile('data.txt', 'utf8');

// 쓰기 (없으면 생성, 있으면 덮어씀)
await writeFile('out.txt', '내용', 'utf8');

// 디렉터리 생성 (중간 경로도 함께)
await mkdir('a/b/c', { recursive: true });

// 파일 존재 확인
const exists = fs.existsSync('file.txt');  // 동기 OK (단순 확인용)
🛤️path — 경로 처리
path 기본 사용법
const path = require('path');

path.join('a', 'b', 'c.txt')   // 'a/b/c.txt' (OS 구분자)
path.resolve('src', 'app.js')  // 절대 경로
path.basename('/a/b/c.txt')    // 'c.txt'
path.dirname('/a/b/c.txt')     // '/a/b'
path.extname('app.js')         // '.js'
path.parse('/a/b/c.txt')
// { root:'/', dir:'/a/b', base:'c.txt', ext:'.txt', name:'c' }

// 현재 파일 기준 상대 경로 (필수 패턴)
path.join(__dirname, 'data', 'file.json')
경로를 문자열 더하기('src/' + name)로 합치면 OS에 따라 슬래시 방향이 틀립니다. 항상 path.join을 쓰세요.
🌐http / https — 웹 서버
간단한 HTTP 서버
const http = require('http');

http.createServer((req, res) => {
  const { method, url } = req;

  if (method === 'GET' && url === '/') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ ok: true }));
  } else {
    res.writeHead(404);
    res.end('Not Found');
  }
}).listen(3000);
실무에서는 http 모듈을 직접 쓰는 대신 Express나 Fastify를 씁니다. 라우팅·미들웨어 처리가 훨씬 편합니다.

📦 npm — 패키지 관리자

🔒package-lock.json — 버전을 잠그는 파일
  • npm install이 처음 실행되면 자동 생성됩니다.
  • 설치된 패키지의 정확한 버전을 기록 — 다른 환경에서도 완전히 동일한 버전으로 설치됩니다.
  • 반드시 git에 커밋하세요. .gitignore에 절대 넣지 마세요.
  • node_modules/ 폴더는 gitignore, lock 파일은 커밋 — 이 반대가 되면 팀원마다 버전이 달라집니다.

🌐Express로 REST API 만들기
설치
npm install express
app.js — 기본 REST API
const express = require('express');
const app = express();

app.use(express.json());  // JSON 바디 파싱

const items = [{ id: 1, name: '사과' }, { id: 2, name: '바나나' }];

// GET 목록
app.get('/items', (req, res) => {
  res.json(items);
});

// GET 단건
app.get('/items/:id', (req, res) => {
  const item = items.find(i => i.id === Number(req.params.id));
  if (!item) return res.status(404).json({ error: 'Not found' });
  res.json(item);
});

// POST 생성
app.post('/items', (req, res) => {
  const item = { id: items.length + 1, ...req.body };
  items.push(item);
  res.status(201).json(item);
});

// DELETE 삭제
app.delete('/items/:id', (req, res) => {
  const idx = items.findIndex(i => i.id === Number(req.params.id));
  if (idx === -1) return res.status(404).json({ error: 'Not found' });
  items.splice(idx, 1);
  res.status(204).end();
});

app.listen(3000, () => console.log('http://localhost:3000'));
📂디렉터리 파일 목록 읽기
fs/promises + path
const { readdir, stat } = require('fs/promises');
const path = require('path');

async function listFiles(dir) {
  const entries = await readdir(dir, { withFileTypes: true });
  for (const entry of entries) {
    const full = path.join(dir, entry.name);
    if (entry.isDirectory()) {
      console.log(`[DIR]  ${full}`);
    } else {
      const { size } = await stat(full);
      console.log(`[FILE] ${full} (${size}B)`);
    }
  }
}

listFiles('./src').catch(console.error);

async function getUser(id) {
  const res = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}

const user = await getUser(1);
