01 리소스팩 vs 데이터팩
리소스팩은 클라이언트(보이는 것·들리는 것)를 바꾸고, 데이터팩은 서버(게임 규칙·명령어)를 바꿉니다. 커스텀 맵은 보통 둘을 세트로 사용합니다 — 데이터팩이 "무엇이 일어날지"를, 리소스팩이 "어떻게 보이고 들릴지"를 담당.
리소스팩 (assets/)
텍스처 · 모델 · 소리 · 폰트 · 언어 · 셰이더 · GUI
클라이언트에 설치. .minecraft/resourcepacks/ 폴더
데이터팩 (data/)
함수 · 전리품 · 레시피 · 어드밴스먼트 · 월드젠
월드에 설치. 세계폴더/datapacks/ — 테스트 29 참고
공통점
둘 다 pack.mcmeta 필수, ZIP 배포 가능, 네임스페이스 구조 동일
02 리소스팩 폴더 구조 (전체)
# 리소스팩이 건드릴 수 있는 모든 폴더 my_resourcepack/ ├── pack.mcmeta # 필수 — 팩 정보·버전 ├── pack.png # 선택 — 팩 아이콘 (64×64 권장) └── assets/ └── minecraft/ # 바닐라 덮어쓰기 (내 네임스페이스도 가능) ├── textures/ # 모든 그림 (PNG) │ ├── block/ item/ entity/ gui/ │ ├── particle/ environment/ painting/ │ ├── font/ map/ misc/ mob_effect/ │ ├── colormap/ models/(갑옷) trims/ ├── models/ # 3D 모델 JSON │ ├── block/ item/ ├── blockstates/ # 블럭 상태 → 모델 연결 ├── items/ # 1.21.4+ 아이템 모델 정의 ├── sounds/ # OGG 소리 파일 ├── sounds.json # 소리 이벤트 등록 ├── font/ # 폰트 정의 JSON ├── lang/ # 언어 파일 (ko_kr.json 등) ├── texts/ # splashes.txt · credits.json 등 ├── shaders/ # 셰이더 (core / post / include) ├── atlases/ # 텍스처 아틀라스 등록 ├── particles/ # 파티클 텍스처 순서 정의 ├── equipment/ # 1.21.2+ 장비(갑옷) 모델 정의 ├── sounds.json·regional_compliancies.json 등 └── gpu_warnlist.json
💡 assets/minecraft/ 안의 파일은 바닐라를 덮어쓰고, assets/내이름/처럼 새 네임스페이스를 만들면 추가가 됩니다. 커스텀 맵은 보통 둘 다 사용.
03 pack.mcmeta
{ "pack": { "pack_format": 46, // 게임 버전에 맞는 숫자 (아래 표) "description": "§d나만의 리소스팩§r\n§7맵 전용", "supported_formats": [34, 46] // 선택 — 여러 버전 동시 지원 (1.20.2+) } }
⚠ description에는 § 색코드 또는 JSON 텍스트 컴포넌트 사용 가능. pack_format이 맞지 않으면 "호환되지 않는 팩" 경고가 뜨지만 대부분 정상 작동합니다.

05 적용 방법 4가지
① resourcepacks 폴더
.minecraft/resourcepacks/ 에 넣고 설정 → 리소스팩
가장 기본. 폴더째로 넣어도 되고 ZIP으로 넣어도 됨
② 월드 내장 resources.zip
세계 폴더 안에 resources.zip 이름으로 넣기
그 월드에 들어가면 자동 적용 — 배포 맵의 정석! 맵 폴더 하나만 공유하면 끝
③ 서버 강제 적용
server.properties → resource-pack=URL
require-resource-pack=true로 거부 시 접속 차단. resource-pack-sha1로 캐시 관리
④ 기본팩으로 승격
options.txt의 resourcePacks 목록 — 런처 프로필별 자동 적용 구성 가능
F3 + T = 리소스팩 새로고침 (게임 재시작 불필요!) · F3 + S = 소리 포함 강제 리로드. 제작 중에는 ZIP 말고 폴더 상태로 두고 F3+T로 즉시 확인하는 게 빠릅니다.

01 텍스처 교체 — 가장 쉬운 것부터
바닐라와 같은 경로·같은 이름으로 PNG를 넣으면 그냥 바뀝니다. 예: assets/minecraft/textures/item/diamond_sword.png를 넣으면 다이아몬드 검 텍스처 교체 끝.
textures/block/*.png
블럭 텍스처 (16×16 기본, 배수 해상도 가능)
textures/item/*.png
아이템 텍스처
textures/entity/**
몹·보트·화살 등 엔티티 스킨 (UV 전개도 형태 — 원본 위에 그리기)
textures/gui/**
인벤토리·체력바·핫바·컨테이너 등 UI 전부 (1.20.2+ sprites/ 분리)
textures/environment/*
해(sun.png)·달(moon_phases.png)·비·눈·구름·엔드 하늘
textures/painting/*
그림 액자 — 맵에서 커스텀 일러스트 걸 때 애용
textures/particle/*
파티클 텍스처 (particles/*.json으로 프레임 순서 제어)
textures/colormap/*
grass.png·foliage.png — 바이옴별 풀·나뭇잎 색상표
textures/misc/*
인더밴트(포탈 반짝임)·펌킨블러(호박 시야)·조준점 등
textures/map/*
지도 아이콘·지도 배경
textures/mob_effect/*
물약 효과 아이콘
textures/trims/* · models/armor/*
갑옷 장식(도금)·갑옷 착용 텍스처 (1.21.2+는 equipment/ 정의와 연동)
💡 투명도(알파 채널) 지원. 반투명은 블럭 종류에 따라 렌더 타입이 달라 안 될 수 있음 (유리류는 OK).
02 텍스처 애니메이션 (.mcmeta)
텍스처 PNG를 세로로 프레임을 이어붙이고, 같은 이름에 .png.mcmeta 파일을 추가하면 애니메이션이 됩니다. 용암·물·마그마가 이 방식.
// stone.png (16×64 = 16×16 프레임 4장) + stone.png.mcmeta { "animation": { "frametime": 4, // 프레임당 틱 수 (4틱 = 0.2초) "interpolate": true, // 프레임 사이 부드럽게 보간 "frames": [0, 1, 2, 3, 2, 1] // 재생 순서 (생략 시 위→아래 순서) } }
활용: 움직이는 TV 화면, 깜빡이는 네온사인, 흐르는 폭포 소품, 빛나는 룬 문자 등 — 맵 분위기 연출의 핵심 도구.
03 blockstates — 블럭 상태 → 모델 연결
// assets/minecraft/blockstates/note_block.json — 상태별로 다른 모델 { "variants": { "instrument=harp,note=0,powered=false": { "model": "mypack:block/custom_chair" }, "": { "model": "minecraft:block/note_block" } // 기본값 } } // 랜덤 배리에이션 — 같은 상태에 모델 여러 개 (돌·풀이 이 방식) { "variants": { "": [ { "model": "block/stone", "weight": 3 }, { "model": "block/stone", "y": 90 }, // 90도 회전 { "model": "block/stone_alt" } ] } }
💡 노트블럭·버섯블럭 기법: 상태 조합이 많은 블럭(노트블럭 1,150개, 버섯블럭 64개)의 상태마다 다른 모델을 연결하면 새 블럭 수백 개를 만드는 효과 — 커스텀 맵 가구·장식의 고전 기법. 데이터팩으로 setblock해서 배치 (테스트 29의 "커스텀 블럭" 참고).
04 모델 JSON 구조

평면 아이템 (layer0~layer4 겹치기 가능 — 물약처럼 색만 다른 레이어)

05 custom_model_data — 아이템 하나로 모델 무한 추가 ~1.21.3 방식
커스텀 맵의 핵심 기술. 바닐라 아이템에 CustomModelData 값을 붙이면 같은 아이템이 다른 모델로 보입니다. 종이(paper) 하나로 가구·음식·무기 수천 종을 만드는 방식.
// assets/minecraft/models/item/paper.json — overrides 방식 (1.21.3까지) { "parent": "minecraft:item/generated", "textures": { "layer0": "minecraft:item/paper" }, "overrides": [ { "predicate": { "custom_model_data": 1 }, "model": "mypack:item/chair" }, { "predicate": { "custom_model_data": 2 }, "model": "mypack:item/table" }, { "predicate": { "custom_model_data": 3 }, "model": "mypack:item/burger" } ] } # 지급 명령어 (1.20.5+ 컴포넌트 문법) /give @s paper[custom_model_data=1] # 1.20.4 이하: /give @s paper{CustomModelData:1}
💡 관례: 자주 쓰는 베이스 아이템은 paper · carrot_on_a_stick(우클릭 감지용) · warped_fungus_on_a_stick. 번호는 팀별로 대역을 나눠 충돌 방지 (예: 가구 1000번대, 음식 2000번대).
06 items/ 아이템 정의 1.21.4+ 새 방식
1.21.4부터 assets/네임스페이스/items/아이템.json이 아이템 모델을 결정합니다. overrides/predicate 대신 셀렉터 트리 구조 — 더 강력하지만 구버전과 호환 안 됨.
// assets/minecraft/items/paper.json — custom_model_data 분기 (1.21.4+) { "model": { "type": "minecraft:select", "property": "minecraft:custom_model_data", // strings 값으로 분기 "cases": [ { "when": "chair", "model": { "type": "minecraft:model", "model": "mypack:item/chair" } }, { "when": "burger", "model": { "type": "minecraft:model", "model": "mypack:item/burger" } } ], "fallback": { "type": "minecraft:model", "model": "minecraft:item/paper" } } } # 이제 CMD는 숫자 대신 문자열도 가능 /give @s paper[custom_model_data={strings:["chair"]}]
type: model
모델 직접 지정 (말단 노드)
type: select
속성값으로 분기 — custom_model_data · display_context · main_hand · charge_type 등
type: condition
true/false 분기 — using_item · broken · damaged · fishing_rod/cast 등
type: range_dispatch
숫자 범위 분기 — damage · count · cooldown · time · compass 등 (활 당김 단계가 이 방식)
type: composite
모델 여러 개 겹치기
special (head·shield·trident…)
특수 렌더러 필요 아이템
⚠ 어느 방식을 쓸지는 목표 게임 버전으로 결정: 1.21.3 이하 → overrides, 1.21.4+ → items/. 두 버전 다 지원하려면 둘 다 넣으면 됩니다 (구버전은 items/ 무시, 신버전은 overrides 무시).
07 atlases — 커스텀 텍스처 폴더 등록

🔊 소리
sounds.json · 커스텀 소리 추가 · /playsound · 카테고리 · 바닐라 소리 이벤트 목록 (전체 약 1,600개 중 실전 핵심)
01 커스텀 소리 추가 — 전체 흐름
소리는 덮어쓰기(바닐라 소리 파일 교체)와 신규 등록(sounds.json에 새 이벤트 추가) 두 가지. 맵 제작은 거의 항상 신규 등록 — 바닐라 소리를 건드리지 않아 안전합니다.
# 1) OGG 파일 배치 assets/mypack/sounds/bgm/title.ogg assets/mypack/sounds/voice/npc_hello.ogg # 2) 소리 이벤트 등록 — assets/mypack/sounds.json { "bgm.title": { "sounds": [ { "name": "mypack:bgm/title", "stream": true } ] // stream:true = 긴 음악용 (메모리에 안 올리고 스트리밍 — BGM은 필수!) }, "voice.npc_hello": { "subtitle": "NPC가 인사한다", // 자막 (lang 키도 가능) "sounds": [ { "name": "mypack:voice/npc_hello", "volume": 1.0, "pitch": 1.0 }, { "name": "mypack:voice/npc_hello2", "weight": 2 } // 여러 개 넣으면 랜덤 재생 (weight = 확률 가중치) ] } } # 3) 재생 /playsound mypack:bgm.title music @a /playsound mypack:voice.npc_hello voice @a ~ ~ ~ 1.0 1.0 0.3 # 소리이벤트 카테고리 대상 좌표 볼륨 피치 최소볼륨 /stopsound @a music mypack:bgm.title # 정지 (카테고리·이벤트 생략 가능)
⚠ 반드시 .ogg (Vorbis) 포맷 + 모노 권장(스테레오는 위치 무시 전역 재생 → BGM은 스테레오, 효과음은 모노). 파일명은 소문자·숫자·_만. 볼륨은 1.0 초과 시 들리는 거리만 늘어남(16블럭×볼륨).
💡 피치 범위 0.5~2.0. 같은 소리도 피치를 바꾸면 완전히 다른 효과음처럼 들려서, 효과음 하나로 여러 연출을 만들 수 있습니다.

01 폰트 정의 — font/*.json
폰트는 글자 모양 교체를 넘어서 커스텀 맵 UI 제작의 비밀 병기입니다. 임의의 PNG를 "글자"로 등록하면 채팅·타이틀·액션바·책에 이미지를 출력할 수 있기 때문.
// assets/minecraft/font/default.json — 기본 폰트에 글리프 추가/교체 // assets/mypack/font/ui.json — 새 폰트 만들기 (권장) { "providers": [ { "type": "bitmap", "file": "mypack:font/dialog_box.png", // textures/font/dialog_box.png "height": 100, // 표시 높이 (기본 8) — 크게 = 풀스크린 이미지 가능 "ascent": 50, // 기준선 위 높이 — 세로 위치 조절 (height 이하) "chars": [""] // 이 문자를 치면 이 이미지가 나옴 }, { "type": "space", // 1.19+ 공백 프로바이더 "advances": { "": -100, "": 4 } // 음수 = 커서를 왼쪽으로! → 이미지 위에 글자 겹치기 가능 }, { "type": "reference", "id": "minecraft:include/default" } // 기본 글자 포함 ] } # 사용 — tellraw·title·actionbar·item name 어디든 /tellraw @a {"text":"","font":"mypack:ui"} /title @a actionbar {"text":"체력 ❤❤❤","font":"mypack:ui"}
💡 커스텀 글리프는 사용자 영역(Private Use Area) U+E000~U+F8FF를 쓰는 것이 관례 — 실제 글자와 충돌하지 않습니다.
02 폰트 프로바이더 종류
bitmap
PNG 이미지 글리프
chars 배열에 여러 줄 넣으면 이미지를 격자로 잘라 배정. 한글 폰트도 이 방식으로 제작 가능
space
글자폭 지정 (1.19+)
음수 폭이 핵심 — UI 겹치기·정렬의 필수 도구
ttf
트루타입 폰트
font/*.ttf — 실제 폰트 파일 사용 (한글 폰트 교체가 쉬움). size·oversample·shift·skip 옵션
unihex
유니코드 hex 폰트 (1.20+)
바닐라 CJK 글리프가 이 방식 (구 legacy_unicode 대체)
reference
다른 폰트 정의 포함 (1.20+)
include/default·include/space 재사용

04 심화 — 셰이더 (shaders/)
리소스팩 셰이더는 코어 셰이더(게임 렌더링 GLSL 교체)와 포스트 이펙트(화면 후처리) 두 종류. 크리퍼 시점의 초록 화면, 스펙테이터로 엔더맨 빙의 시 반전 화면이 포스트 이펙트입니다.

마플·토템 등 유명 유튜버/맵 제작 팀 스타일의 콘텐츠 맵에서 공통적으로 쓰이는 구현 방식 총정리
01 전문 맵 제작의 기본 공식
퀄리티 높은 콘텐츠 맵은 예외 없이 「리소스팩(보이는 것·들리는 것) + 데이터팩(게임 로직) + 월드(세트장)」 3종 세트입니다. 유튜버 콘텐츠 맵(상황극·탈출맵·미니게임)의 "모드 같은데 모드가 아닌" 연출이 전부 이 조합.
① 기획
필요한 소품·효과음·UI를 목록화 → CMD 번호표·소리 이벤트 이름 규칙 먼저 정하기
② 세트장
WorldEdit/Axiom(모드, 제작 단계에서만 사용)으로 지형·건축 → 배포본은 바닐라
③ 리소스팩
Blockbench 소품 모델 + Audacity 효과음/성우 녹음 + 폰트 UI
④ 데이터팩
진행 로직·트리거·연출 타이밍 (playsound·particle·title 호출)
⑤ 배포
월드에 resources.zip 내장 or 서버 강제 적용 → 시청자 배포판은 폴더 하나로 끝
02 소품(가구·음식·장식) 배치 — 3대 기법
A. 디스플레이 엔티티 1.19.4+ 정석

B. 투명 아이템 액자

C. 갑옷 거치대
