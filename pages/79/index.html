🚀 로블록스 개발 시작하기
로블록스에서 게임(공식 명칭은 익스피리언스 / Experience)을 만드는 건 전부 Roblox Studio라는 무료 프로그램 안에서 이뤄집니다. 맵을 짓는 것도, 코드를 쓰는 것도, 테스트도, 배포도 전부 여기서 합니다. 코드는 Luau(루아우)라는 언어를 씁니다 — Lua 5.1을 로블록스가 개조한 것입니다.

📥 설치와 준비

💻Studio 설치
  1. roblox.com 에서 계정을 만듭니다 (게임 플레이 계정과 동일합니다).
  2. create.roblox.com 접속 → Start Creating → Studio 설치 파일이 내려받아집니다.
  3. 설치 후 로그인하면 새 익스피리언스 만들기 화면이 뜹니다.
  4. 템플릿을 고릅니다. 처음이면 Baseplate(빈 회색 바닥판)가 가장 깔끔합니다.
💡
기기 요건: Studio는 Windows / macOS 전용입니다. 아이패드·안드로이드·크롬북에서는 정식 Studio가 돌아가지 않습니다. 로블록스가 브라우저 기반 편집 환경을 계속 확장하고 있으므로, 실제로 쓰기 전에 create.roblox.com 에서 현재 지원 기기를 확인하세요.

🖥 Studio 화면 구성

🌲Explorer (탐색기)필수
게임 안의 모든 물건이 트리로 보이는 창입니다. 파트 하나, 스크립트 하나까지 전부 여기 있습니다. View 탭 → Explorer 로 켭니다. 이게 없으면 아무것도 못 합니다.
🔧Properties (속성)필수
Explorer에서 고른 물건의 속성값을 보고 고치는 창입니다. 크기·색·위치·고정 여부 전부 여기서 바꿉니다. View 탭 → Properties.
📤Output (출력)필수
print() 결과와 오류 메시지가 뜨는 창입니다. 빨간 글씨는 오류, 노란 글씨는 경고입니다. View 탭 → Output. 코딩할 때 항상 켜두세요.
⌨️Command Bar
코드 한 줄을 즉석에서 실행하는 입력창입니다. 파트 100개 한 번에 만들기, 속성 일괄 변경 같은 작업에 아주 유용합니다. View 탭 → Command Bar.
🧰Toolbox
다른 사람이 올린 모델·이미지·사운드를 가져오는 창입니다. 편하지만 악성 스크립트가 숨어 있는 모델이 흔하니, 가져온 모델은 반드시 Explorer에서 스크립트가 들어 있는지 확인하세요.
📦Asset Manager
내가 올린 이미지·사운드·메시·패키지를 관리합니다. 3D 모델(.fbx/.obj) 가져오기도 여기서 합니다.

👋 첫 스크립트

✍️3분 안에 되는 것
  1. Explorer에서 ServerScriptService 위에 마우스를 올리고 ➕ 클릭
  2. Script 선택 → 코드 편집기가 열립니다
  3. 아래 코드를 붙여넣고 F5
  4. Output 창에 글자가 찍히면 성공입니다
🌟 첫 스크립트 — 접속한 사람 환영하기Script · ServerScriptService
local Players = game:GetService("Players")

-- 누군가 게임에 들어오면 이 함수가 실행된다
Players.PlayerAdded:Connect(function(player)
	print(player.Name .. "님 환영합니다!")

	-- 캐릭터가 생성되면(리스폰 포함) 실행
	player.CharacterAdded:Connect(function(character)
		local humanoid = character:WaitForChild("Humanoid")
		humanoid.WalkSpeed = 32   -- 기본값 16의 두 배로 빠르게
	end)
end)

  • 다른 언어를 해본 사람 — Luau 문법을 훑고 바로 API 기본 → 서비스 → 서버·클라이언트로 가세요
  • 급한 사람 — 실전 코드 탭에 복사해서 바로 쓰는 예제가 모여 있습니다
  • 막혔을 때 — 디버깅·최적화 탭의 초보가 가장 많이 겪는 오류를 먼저 확인하세요
🧱 맵 만들기 — 빌딩 전 과정
로블록스 맵은 결국 파트(Part)라는 상자를 쌓아 만듭니다. 여기에 지형(Terrain), 메시(MeshPart), 조명, 재질을 얹으면 그럴듯한 공간이 됩니다. 마우스로 짓는 방법과 코드로 짓는 방법을 같이 정리합니다.

🧱 코드로 파트 만들기 — 가장 기본Script
local part = Instance.new("Part")
part.Name = "MyFloor"
part.Size = Vector3.new(20, 1, 20)          -- 가로20 높이1 세로20
part.Position = Vector3.new(0, 5, 0)        -- Y가 높이
part.Anchored = true                        -- 안 하면 떨어진다
part.Material = Enum.Material.WoodPlanks
part.Color = Color3.fromRGB(120, 80, 40)
part.TopSurface = Enum.SurfaceType.Smooth

-- Parent 는 모든 설정을 끝낸 뒤 마지막에 넣는 것이 성능에 좋다
part.Parent = workspace
⚡
Parent는 항상 마지막에. Instance.new("Part", workspace) 처럼 두 번째 인자로 부모를 주는 방식은 권장되지 않습니다. 부모에 넣는 순간부터 물리·렌더링이 그 파트를 추적하기 시작하므로, 속성을 다 정한 뒤 넣어야 불필요한 재계산이 없습니다.

📦 모델 — 여러 파트 묶기

🗃Model 사용법
  • 파트 여러 개를 고르고 Ctrl+G 를 누르면 Model 하나로 묶입니다
  • 모델은 통째로 옮기고, 복제하고, 저장할 수 있습니다
  • PrimaryPart 를 지정하면 그 파트가 모델의 기준점이 됩니다
  • 이동은 model:PivotTo(cframe) — 구형 SetPrimaryPartCFrame 은 사용 중단됨
  • 현재 위치는 model:GetPivot() 로 얻습니다
  • 크기 범위는 model:GetExtentsSize(), 경계는 model:GetBoundingBox()
📦 모델 통째로 옮기기 · 복제하기Script
local ServerStorage = game:GetService("ServerStorage")
local house = ServerStorage:WaitForChild("House")

-- 5칸 간격으로 집 5채 배치
for i = 1, 5 do
	local copy = house:Clone()
	copy:PivotTo(CFrame.new(i * 40, 0, 0))   -- 모델 전체를 이 위치로
	copy.Parent = workspace
end

-- 회전까지 같이
local target = CFrame.new(0, 10, 0) * CFrame.Angles(0, math.rad(90), 0)
house:Clone():PivotTo(target)

✂️ 솔리드 모델링 (Union · Negate)

🔨모양 깎아내기
  • Union(합집합) — 파트 여러 개를 골라 Model 탭 → Union. 하나의 UnionOperation 이 됩니다
  • Negate(빼기) — 파트를 Negate 한 뒤 다른 파트와 Union 하면 그 모양만큼 구멍이 뚫립니다. 창문·문 만들 때 사용
  • Separate — 유니온을 다시 분해
  • CollisionFidelity — 충돌 정밀도. Box → Hull → Default → PreciseConvexDecomposition 순으로 정확하지만 무거워집니다
  • RenderFidelity — 화면 표시 정밀도. Automatic 이면 멀 때 단순화됩니다
⚠️
유니온을 남발하면 게임이 무거워집니다. 특히 CollisionFidelity 를 PreciseConvexDecomposition 으로 둔 유니온이 많으면 물리 계산이 급격히 늘어납니다. 장식용이라 부딪힐 일이 없으면 CanCollide 를 끄고 CollisionFidelity 를 Box 로 두세요.

🏔 지형 (Terrain)

⛰지형 편집기Model 탭
파트가 아닌 복셀(voxel) 기반 지형입니다. 산·강·동굴 같은 자연 지형에 씁니다. Model 탭 → Editor 로 엽니다.
  • Generate — 산·바다·사막을 자동 생성. 시드·크기·바이옴 선택
  • Import — 하이트맵 이미지로 지형 생성
  • Region — 영역 선택 후 이동·복사·삭제·채우기
  • Add / Subtract — 흙을 붙이거나 파냄
  • Grow / Erode — 기존 표면을 부풀리거나 깎음
  • Smooth — 울퉁불퉁한 면을 매끄럽게
  • Flatten — 평평하게 (건물 지을 터 만들기)
  • Paint — 재질만 바꿈 (잔디 → 모래 등)
  • Sea Level — 지정 높이까지 물로 채우거나 비움
🏔 코드로 지형 만들기Script
local Terrain = workspace.Terrain

-- 직육면체 영역을 바위로 채우기
Terrain:FillBlock(
	CFrame.new(0, 0, 0),          -- 중심 위치·회전
	Vector3.new(100, 20, 100),    -- 크기
	Enum.Material.Rock
)

-- 구 모양으로 물 채우기 (호수)
Terrain:FillBall(Vector3.new(0, 10, 0), 25, Enum.Material.Water)

-- 영역 비우기 (동굴 파기)
Terrain:FillBall(Vector3.new(0, 5, 0), 12, Enum.Material.Air)

-- 재질 색 바꾸기
Terrain:SetMaterialColor(Enum.Material.Grass, Color3.fromRGB(90, 140, 60))

-- 특정 재질을 다른 재질로 통째 치환
local region = Region3.new(Vector3.new(-100,-50,-100), Vector3.new(100,50,100))
Terrain:ReplaceMaterial(region, 4, Enum.Material.Sand, Enum.Material.Snow)

-- 전체 지형 삭제
-- Terrain:Clear()

🎨 재질과 텍스처

🧪Material Manager

외부 3D 프로그램(Blender 등)에서 만든 모델을 넣는 파트입니다. Asset Manager → Bulk Import 또는 3D Importer 로 .fbx/.obj 를 올립니다.

📦 모듈 정의 — 반드시 테이블(또는 값) 하나를 returnModuleScript · ReplicatedStorage/Utils
local Utils = {}

-- 두 위치 사이 거리
function Utils.distance(a: Vector3, b: Vector3): number
	return (a - b).Magnitude
end

-- 숫자에 천 단위 콤마 (1234567 -> "1,234,567")
function Utils.comma(n: number): string
	local s = tostring(math.floor(n))
	local out = s:reverse():gsub("(%d%d%d)", "%1,"):reverse()
	return (out:gsub("^,", ""))
end

-- 테이블에서 무작위 하나 뽑기
function Utils.pick(list)
	return list[math.random(1, #list)]
end

return Utils   -- 이 줄이 없으면 오류가 납니다

🧭CFrame 이 뭔가

local npc = workspace.NPC
local humanoid = npc:WaitForChild("Humanoid")

local path = PathfindingService:CreatePath({
	AgentRadius = 2,
	AgentHeight = 5,
	AgentCanJump = true,
	AgentMaxSlope = 45,
})

local function walkTo(destination: Vector3)
	local ok = pcall(function()
		path:ComputeAsync(npc.PrimaryPart.Position, destination)
	end)

	if not ok or path.Status ~= Enum.PathStatus.Success then
		warn("경로를 찾지 못했습니다")
		return
	end

	for _, waypoint in path:GetWaypoints() do
		if waypoint.Action == Enum.PathWaypointAction.Jump then
			humanoid.Jump = true
		end
		humanoid:MoveTo(waypoint.Position)
		local reached = humanoid.MoveToFinished:Wait()

🔌 서버 · 클라이언트 통신
로블록스는 서버 하나 + 클라이언트 여러 개 구조입니다. 둘은 메모리를 공유하지 않으므로 대화를 하려면 리모트가 필요합니다. 여기를 대충 만들면 곧바로 핵·치트에 뚫립니다.
[클라이언트 A] [클라이언트 B] │ │ │ FireServer() │ ▼ ▼ ┌─────────────────────────────────┐ │ 서 버 │ ← 여기만 신뢰할 수 있음 │ · 검증 · 데이터 · 보상 지급 │ └─────────────────────────────────┘ │ FireClient() / FireAllClients() ▼ [모든 클라이언트에 반영]

📨 RemoteEvent — 단방향 (응답 없음)

방향보내는 쪽받는 쪽
클라 → 서버remote:FireServer(...)remote.OnServerEvent:Connect(function(player, ...))
서버 → 클라 1명remote:FireClient(player, ...)remote.OnClientEvent:Connect(function(...))
서버 → 전원remote:FireAllClients(...)remote.OnClientEvent:Connect(...)
⚡
OnServerEvent 의 첫 번째 인자는 항상 player 입니다. 클라이언트가 보내지 않아도 엔진이 자동으로 끼워 넣습니다. 그래서 "누가 보냈는지"는 위조할 수 없습니다 — 이게 서버 검증의 출발점입니다.

local ReplicatedStorage = game:GetService("ReplicatedStorage")
local buyItem = ReplicatedStorage:WaitForChild("BuyItem")

local PRICES = { Sword = 100, Bow = 150, Staff = 200 }

buyItem.OnServerEvent:Connect(function(player, itemName)
	-- 1) 타입 검사 — 클라이언트는 아무 값이나 보낼 수 있습니다
	if type(itemName) ~= "string" then return end

	-- 2) 존재 검사

	if not price then return end

	-- 3) 소지금 검사 (서버가 가진 값으로만)
	local coins = player.leaderstats.Coins
	if coins.Value < price then
		return
	end

	-- 4) 실제 처리
	coins.Value -= price
	local tool = ReplicatedStorage.Weapons[itemName]:Clone()
	tool.Parent = player.Backpack
end)

local Players = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local openChest = ReplicatedStorage:WaitForChild("OpenChest")

local COOLDOWN = 1        -- 초
local MAX_DISTANCE = 15   -- 스터드
local lastUse = {}

Players.PlayerRemoving:Connect(function(p)
	lastUse[p] = nil       -- 나간 사람 기록 정리 (메모리 누수 방지)
end)

openChest.OnServerEvent:Connect(function(player, chest)
	-- 쿨다운
	local now = os.clock()
	if lastUse[player] and now - lastUse[player] < COOLDOWN then return end
	lastUse[player] = now

	-- 타입·소속 검사
	if typeof(chest) ~= "Instance" or not chest:IsA("BasePart") then return end
	if not chest:IsDescendantOf(workspace.Chests) then return end

	-- 거리 검사
	local char = player.Character
	local root = char and char:FindFirstChild("HumanoidRootPart")
	if not root then return end
	if (root.Position - chest.Position).Magnitude > MAX_DISTANCE then return end

	-- 이미 열린 상자인지
	if chest:GetAttribute("Opened") then return end
	chest:SetAttribute("Opened", true)

	-- 보상 지급
	player.leaderstats.Coins.Value += 50
end)

local Players = game:GetService("Players")
local DataStoreService = game:GetService("DataStoreService")
local store = DataStoreService:GetDataStore("PlayerData_v1")

local DEFAULT = { coins = 0, level = 1 }
local cache = {}                    -- 접속 중 데이터를 메모리에 들고 있음

local function key(player)
	return "p_" .. player.UserId
end

-- 재시도까지 하는 안전한 불러오기
local function load(player)
	for attempt = 1, 3 do
		local ok, result = pcall(function()
			return store:GetAsync(key(player))
		end)
		if ok then
			return result or table.clone(DEFAULT)
		end
		warn("불러오기 실패", attempt, result)
		task.wait(2 ^ attempt)      -- 2초, 4초, 8초 (지수 백오프)
	end
	return nil                      -- 끝내 실패
end

local function save(player)
	local data = cache[player]
	if not data then return end

	local ok, err = pcall(function()
		store:SetAsync(key(player), data)
	end)
	if not ok then warn("저장 실패:", err) end
end

Players.PlayerAdded:Connect(function(player)
	local data = load(player)

	if not data then
		-- ⚠️ 불러오기 실패 시 기본값을 주면 기존 데이터가 날아갑니다
		player:Kick("데이터를 불러오지 못했습니다. 다시 접속해 주세요.")
		return
	end

		data.coins = v              -- 값이 바뀌면 캐시에 반영
	end)
end)

end)

📉호출 한도

👥중복 접속 (세션 잠금)

📦저장 가능한 타입

🕳배열 구멍 주의

🔢버전 관리

obj:GetFullName() 은 전체 경로를 문자열로 줍니다. debug.traceback() 은 어떤 경로로 이 함수가 불렸는지 보여줍니다.

효과가 큰 것부터
항목내용
StreamingEnabledWorkspace 속성. 넓은 맵에서 가까운 부분만 로드합니다. 대형 맵이면 거의 필수
파트 수 줄이기안 보이는 뒷면·바닥 밑 파트를 지우세요. 유니온·메시로 합치는 것도 방법
CastShadow 끄기작은 장식은 그림자를 끄면 체감이 큽니다
광원 수 제한PointLight·SpotLight 는 비쌉니다. Neon 재질로 대체 가능하면 그쪽이 쌉니다
Anchored 켜기움직이지 않는 파트는 전부 고정. 물리 계산에서 빠집니다
CanCollide·CanTouch·CanQuery 끄기장식용 파트는 셋 다 끄면 충돌·판정 비용이 사라집니다
while 루프에 wait양보 없는 루프는 서버를 통째로 멈춥니다
이벤트 Disconnect안 쓰는 연결은 반드시 끊으세요. 메모리 누수의 1순위
클라이언트로 넘기기이펙트·UI·소리는 각자 기기에서 처리하면 서버가 가벼워집니다
루프 밖으로 빼기GetService·GetChildren 같은 걸 매 프레임 호출하지 마세요
⚡ 나쁜 예 vs 좋은 예
-- ❌ 나쁨 : 매 프레임 전체 순회 + 서비스 재조회
game:GetService("RunService").Heartbeat:Connect(function()
	for _, player in game:GetService("Players"):GetPlayers() do
		for _, part in workspace:GetDescendants() do
			-- 수천 번 반복 → 프레임 급락
		end
	end
end)

-- ✅ 좋음 : 서비스는 위에서 한 번, 검사 주기는 필요한 만큼만
local Players = game:GetService("Players")
local targets = workspace.Targets:GetChildren()   -- 미리 캐시

task.spawn(function()
	while true do
		for _, player in Players:GetPlayers() do
			-- 필요한 것만
		end
		task.wait(0.2)          -- 초당 5번이면 충분한 일이 많습니다
	end
end)

-- ❌ 나쁨 : 연결을 쌓기만 함
part.Touched:Connect(function() end)   -- 계속 새로 만들면 누적됨

-- ✅ 좋음 : 필요 없어지면 끊기
local conn
conn = part.Touched:Connect(function()
	conn:Disconnect()
end)

🚢 게시 · 설정 · 수익화
만든 게임을 실제로 사람들이 들어올 수 있게 올리고, 설정을 잡고, 수익을 내는 과정입니다.

📤 게시하기

  1. File → Publish to Roblox (첫 게시는 Ctrl+Alt+P)
  2. 이름·설명을 적고 Create
  3. 게시 후 Home 탭 → Game Settings 에서 세부 설정
  4. Permissions 탭에서 공개 범위를 Public 으로 바꿔야 남들이 들어올 수 있습니다
  5. 이후에는 Ctrl+P 로 덮어쓰기 게시. 게시하는 순간 실서버에 반영됩니다
📌
용어 정리 — Experience(익스피리언스) 는 게임 전체, Place(플레이스) 는 그 안의 개별 맵입니다. 하나의 익스피리언스에 여러 플레이스를 두고 TeleportService 로 오갈 수 있습니다. 처음 만든 플레이스가 시작 플레이스가 됩니다.

💰 수익화 수단

🎟게임패스 (Game Pass)
한 번 사면 영구. VIP, 특수 무기, 배속 같은 데 씁니다. UserOwnsGamePassAsync 로 소유 여부를 확인합니다.
🧪개발자 상품 (Developer Product)
여러 번 살 수 있음. 코인 충전, 부활권 등. ProcessReceipt 로 처리하며 게임 전체에 하나만 정의해야 합니다.
🚪유료 입장 · 프라이빗 서버
입장 자체를 유료로 하거나, 개인 서버를 월정액으로 팝니다. Game Settings → Monetization 에서 켭니다.
📈참여 기반 지급
프리미엄 가입자가 게임에서 보낸 시간에 비례해 지급되는 수익입니다. 따로 코딩할 것은 없고, 체류 시간이 길수록 유리합니다.
💵
로벅스를 현금으로 바꾸려면(DevEx) 최소 보유량·연령·계정 상태 등 자격 요건을 충족해야 하고, 환전 비율과 조건은 로블록스가 수시로 조정합니다. 수익 계획을 세우기 전에 create.roblox.com 의 현재 DevEx 안내를 직접 확인하세요.

📜 지켜야 할 규정

  • 커뮤니티 규정 — 폭력·선정성·도박 요소·현실 상품 거래는 게임 삭제 사유입니다
  • 연령 등급 — 콘텐츠 설문(Experience Guidelines)을 작성해야 공개할 수 있습니다
  • 저작권 — 남의 이미지·음악·모델을 무단으로 올리면 계정 제재를 받습니다
  • 채팅 필터 — 사용자가 입력한 문자열을 화면에 표시할 땐 TextService:FilterStringAsync 로 걸러야 합니다
  • 백도어 주의 — Toolbox 모델에 숨은 스크립트가 게임을 탈취하는 사례가 많습니다
  • 규정은 자주 바뀌므로 공식 문서를 최종 기준으로 삼으세요
