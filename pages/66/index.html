CIA 삼각형 & 보안 기초 원칙

정보 보안의 모든 목표는 CIA Triad로 귀결된다. 세 요소 중 하나라도 침해되면 보안 사고다.

🔒C — 기밀성 (Confidentiality)
정의: 인가된 사용자만 정보에 접근 가능.

위협: 도청, 스니핑, 계정 탈취, 중간자 공격(MitM).

보호 수단: 암호화(AES, RSA), 접근 제어(ACL), VPN, 최소 권한 원칙(PoLP).

예시 침해: 데이터베이스 덤프 유출, 평문 비밀번호 전송.
✅I — 무결성 (Integrity)
정의: 정보가 허가 없이 변조되지 않음을 보장.

위협: 중간자 공격, SQL Injection, 파일 변조, 로그 조작.

보호 수단: 해시(SHA-256), 디지털 서명, HMAC, 체크섬, 감사 로그.

예시 침해: 금융 거래 금액 변조, 악성코드 삽입.
⚡A — 가용성 (Availability)
정의: 인가된 사용자가 필요할 때 서비스에 접근 가능.

위협: DDoS, 랜섬웨어, 하드웨어 장애, 서비스 과부하.

보호 수단: 이중화(HA), CDN, DDoS 방어, 백업, 로드밸런싱.

예시 침해: 서버 다운, 병원 IT 시스템 랜섬웨어 마비.

웹 공격 — OWASP Top 10 (2021)
⚠ 주의

A01Broken Access Control — 취약한 접근 제어Critical
설명: 인가되지 않은 기능·데이터에 접근 가능. 가장 흔한 취약점.
예시: URL 직접 접근 (/admin/), IDOR (타인 리소스 접근), 수평적 권한 상승.
방어: 서버 측 접근 제어 강제, 최소 권한, 모든 요청 인가 검증.
# 취약한 예: 파라미터로 사용자 결정 GET /api/user?id=1234 # id=1235로 바꾸면 다른 사람 정보 접근 # 방어: 세션 기반으로 현재 로그인 사용자만 접근 user_id = request.session['user_id'] # 파라미터 무시
A02Cryptographic Failures — 암호화 실패Critical
설명: 민감 데이터의 암호화 부재 또는 취약한 암호화 사용.
예시: MD5 비밀번호 저장, HTTP 평문 전송, 하드코딩된 키, ECB 모드 사용.
방어: 강력한 암호화(AES-256), bcrypt/Argon2 비밀번호 해시, HTTPS 강제.
# 취약: MD5 사용 password_hash = md5(password) # 레인보우 테이블로 크랙 가능 # 안전: bcrypt 사용 password_hash = bcrypt.hashpw(password, bcrypt.gensalt(rounds=12))
A03Injection — 인젝션Critical
설명: 신뢰할 수 없는 데이터가 인터프리터로 전달되어 의도치 않은 명령 실행.
유형: SQL Injection, Command Injection, LDAP Injection, NoSQL Injection.
SQL Injection 예시:
# 취약한 쿼리 query = "SELECT * FROM users WHERE name='" + username + "'" # 공격: username = ' OR '1'='1 # 결과: SELECT * FROM users WHERE name='' OR '1'='1' (전체 조회) # 방어: Prepared Statement 사용 query = "SELECT * FROM users WHERE name = ?" cursor.execute(query, (username,))
방어: Parameterized Query / Prepared Statement, ORM, 입력 검증, WAF.
A04Insecure Design — 안전하지 않은 설계High
설명: 구현 버그가 아닌 설계 단계의 보안 결함.
예시: 비밀번호 재설정 로직 취약, 속도 제한 없는 OTP, 보안 설계 없는 아키텍처.
방어: 위협 모델링, 보안 설계 원칙 적용, Secure SDLC.
A05Security Misconfiguration — 보안 설정 오류High
설명: 기본 설정 그대로 사용, 불필요한 기능 활성화, 오류 메시지 과다 노출.
예시: 기본 admin/admin 계정, 디렉터리 리스팅 허용, 스택 트레이스 노출.
방어: 보안 하드닝, 불필요 기능 비활성화, 정기 설정 점검.
A06Vulnerable Components — 취약한 구성 요소High
설명: 알려진 취약점이 있는 라이브러리·프레임워크·컴포넌트 사용.
예시: Log4Shell (Log4j), Heartbleed (OpenSSL), EternalBlue (SMB).
방어: 의존성 최신 유지, SCA(Software Composition Analysis) 도구 사용, 취약점 모니터링.
A07Identification & Auth Failures — 인증 실패High
설명: 취약한 세션 관리, 크레덴셜 스터핑 허용, 취약한 비밀번호 정책.
예시: 세션 ID URL 노출, 로그아웃 후 세션 미삭제, 브루트포스 허용.
방어: MFA, 안전한 세션 관리, 계정 잠금, 비밀번호 복잡도 강제.
A08Software & Data Integrity Failures — 무결성 실패High
설명: 코드·데이터의 무결성 검증 없는 업데이트, 안전하지 않은 역직렬화.
예시: 서명 없는 자동 업데이트, 악성 역직렬화 페이로드, CI/CD 파이프라인 침해.
방어: 디지털 서명 검증, 안전한 역직렬화, CI/CD 보안 강화.
A09Security Logging & Monitoring Failures — 로깅/모니터링 실패Medium
설명: 보안 이벤트 로깅 부재, 모니터링 미비로 침해 탐지 실패.
예시: 로그인 실패 미기록, 의심 활동 알림 없음, 로그 변조 가능.
방어: 중앙 로그 관리(SIEM), 실시간 알림, 로그 무결성 보호.
A10Server-Side Request Forgery (SSRF)High
설명: 서버가 공격자가 지정한 URL로 요청을 전송하도록 유도.
예시: http://example.com/load?url=http://169.254.169.254/metadata (AWS 메타데이터 접근)
방어: URL 화이트리스트, 내부 네트워크 접근 차단, 응답 검증.
+ XSS (Cross-Site Scripting) 심화 ▼
유형설명예시
Reflected XSSURL 파라미터의 스크립트가 즉시 반사?q=<script>alert(1)</script>
Stored XSSDB에 저장된 스크립트가 모든 방문자에 실행게시판 댓글에 스크립트 저장
DOM-based XSSJavaScript가 DOM을 직접 조작하며 발생innerHTML에 사용자 입력 삽입
# 방어: HTML 이스케이프 &lt;script&gt; → 브라우저가 텍스트로만 렌더링 # CSP 헤더로 스크립트 소스 제한 Content-Security-Policy: script-src 'self' https://trusted.com
+ CSRF (Cross-Site Request Forgery) ▼
피해자의 인증된 세션을 이용해 공격자가 원하는 요청을 강제 실행시키는 공격.

공격 흐름:
피해자 로그인 (세션 유지)
→
악성 사이트 방문
→
숨겨진 요청 자동 전송
→

방어: CSRF 토큰, SameSite 쿠키, Referer 검증, Double Submit Cookie.
네트워크 공격 기법
🌊DoS / DDoS
서비스 가용성 침해
DoS: 단일 출처에서 대량 트래픽으로 서비스 마비.
DDoS: 수천~수백만 봇넷에서 동시 공격.

유형:
· Volume-based: UDP Flood, ICMP Flood — 대역폭 소진
· Protocol: SYN Flood, Ping of Death — 연결 리소스 소진
· Application: HTTP Flood, Slowloris — 서버 자원 소진

방어: Rate Limiting, CDN, Anycast, DDoS 방어 서비스(Cloudflare, AWS Shield).
🕵️중간자 공격 (MitM)
기밀성·무결성 침해
공격자가 통신 양 끝 사이에 개입하여 데이터를 도청·변조.

기법:
· ARP Spoofing: 가짜 ARP 응답으로 트래픽 탈취
· DNS Spoofing: 가짜 DNS 응답으로 악성 사이트 리다이렉트
· SSL Strip: HTTPS를 HTTP로 다운그레이드
· Evil Twin: 가짜 Wi-Fi AP 생성

방어: HTTPS 강제(HSTS), 인증서 고정(Pinning), VPN, DNSSEC.
🔍포트 스캔 / 정찰
정보 수집 단계
Nmap 스캔 유형:
· TCP Connect: 완전한 3-way handshake
· SYN (Stealth): half-open, 로그 회피
· UDP: UDP 포트 스캔
· OS Fingerprinting: OS 탐지

nmap -sS -O -p 1-65535 target.com nmap -sV --script vuln target.com
방어: 방화벽, IDS, 불필요 포트 차단, 포트 노킹.
📦패킷 스니핑
기밀성 침해
네트워크 트래픽을 캡처해 평문 데이터 추출.

도구: Wireshark, tcpdump, tshark

위험 시나리오:
· 공개 Wi-Fi에서 HTTP 트래픽 도청
· 스위치드 네트워크 + ARP 스푸핑으로 스니핑

방어: 암호화 프로토콜 사용(HTTPS, SSH, TLS), 스위치드 네트워크, 암호화 Wi-Fi(WPA3).
🔀스푸핑 (Spoofing)
신원 위장
IP Spoofing: 출발지 IP 위조
ARP Spoofing: 가짜 MAC-IP 매핑으로 트래픽 탈취
DNS Spoofing: 가짜 DNS 응답
Email Spoofing: From 헤더 위조

방어:
· IP: 라우터 필터링, Unicast RPF
· ARP: Dynamic ARP Inspection
· DNS: DNSSEC
· Email: SPF, DKIM, DMARC
🔁재전송 공격 (Replay Attack)
인증 우회
유효한 데이터 전송을 캡처해 재전송함으로써 인증 우회.

예시: 인증 토큰 캡처 후 재사용, 결제 요청 재전송.

방어: Nonce(일회용 값), 타임스탬프 검증, 세션 토큰 짧은 만료.
소셜 엔지니어링 (Social Engineering)

기술적 취약점이 아닌 사람의 심리를 이용하는 공격. 가장 성공률이 높은 공격 벡터 중 하나.

🎣피싱 (Phishing)
Phishing: 대량 발송 가짜 이메일/SMS로 자격증명 탈취.
Spear Phishing: 특정 대상 맞춤형 피싱 (더 위험).
Whaling: CEO·임원급 대상 피싱.
Smishing: SMS 피싱.
Vishing: 음성(전화) 피싱.
Pharming: DNS 조작으로 정상 URL을 악성 사이트로 유도.

징후: 긴박감 조성, 문법 오류, 이상한 발신자, 의심스러운 링크.
🎭프리텍스팅 & 베이팅
Pretexting (프리텍스팅): 허구의 시나리오를 만들어 정보 획득. 예: IT 지원팀 직원 사칭.

Baiting (베이팅): 호기심을 자극해 악성 장치 실행 유도. 예: 주차장에 USB 드라이브 방치.

Quid Pro Quo: 도움을 제공하는 척 정보 요청. 예: 가짜 기술 지원.
🚪물리적 침투 기법
Tailgating / Piggybacking: 승인된 직원 뒤를 따라 보안 구역 침입.

Shoulder Surfing: 어깨 너머로 비밀번호·화면 엿보기.

Dumpster Diving: 버려진 문서에서 민감 정보 수집.

방어: 보안 인식 교육, 방문자 절차, 문서 파쇄.
🛡️소셜 엔지니어링 방어
기술적 방어:
· 이메일 필터링 (SPF, DKIM, DMARC)
· MFA 강제
· URL 필터링

인적 방어:
· 정기 보안 인식 교육
· 모의 피싱 훈련
· "확인하고 또 확인" 문화
· 민감 정보 요청 시 공식 채널 재확인
악성코드 (Malware) 완전 정리
🦠바이러스 (Virus)
정상 파일에 코드를 삽입하여 실행 시 전파. 반드시 사용자의 실행이 필요.
종류: 파일 감염형, 부트 섹터형, 매크로 바이러스.
방어: 안티바이러스, 파일 실행 제한.
🐛웜 (Worm)
사용자 개입 없이 네트워크를 통해 자가 복제·전파. 대역폭 소모.
예시: WannaCry (EternalBlue 취약점 이용), Code Red, Slammer.
방어: 패치 적용, 방화벽, 네트워크 분리.
🐴트로이목마 (Trojan)
정상 소프트웨어인 척 숨어 악성 행위 수행.
종류: RAT(Remote Access Trojan), 다운로더, 드로퍼.
예시: Zeus, Emotet, njRAT.
방어: 신뢰된 출처 소프트웨어만 설치, 행위 기반 탐지.
🔒랜섬웨어 (Ransomware)
파일을 암호화하고 복호화 키를 대가로 금전 요구.
공격 흐름: 피싱 → 감염 → 데이터 유출 → 암호화 → 협박.
예시: WannaCry, REvil, LockBit, Ryuk, Conti.
방어: 오프라인 백업(3-2-1 규칙), 패치, EDR, 네트워크 분리.
🕷️스파이웨어 / 애드웨어
스파이웨어: 사용자 몰래 정보(키로깅, 스크린샷, 활동) 수집 후 전송.
키로거: 타이핑 내용 모두 기록 (비밀번호 등).
애드웨어: 광고 표시. 개인정보 수집 병행 가능.
방어: 안티스파이웨어, 행위 기반 탐지.
👻루트킷 (Rootkit)
운영체제 수준에서 존재를 숨기는 악성코드. 가장 제거하기 어렵다.
유형: 커널 루트킷, 부트킷, 하이퍼바이저 루트킷.
탐지: 외부 부팅 후 스캔, 무결성 검증(Tripwire), 메모리 포렌식.
방어: UEFI Secure Boot, 커널 무결성 보호.
🤖봇넷 (Botnet)
공격자가 원격으로 제어하는 감염된 컴퓨터(좀비) 네트워크.
용도: DDoS, 스팸 발송, 크립토재킹, 자격증명 탈취.
C2 통신: IRC, HTTP, P2P, 도메인 생성 알고리즘(DGA).
방어: 감염 방지, 의심 C2 도메인 차단, 네트워크 모니터링.
⛏️크립토재킹 (Cryptojacking)
피해자의 컴퓨팅 자원을 몰래 사용해 암호화폐 채굴.
징후: CPU 사용량 급증, 과열, 전기료 증가, 성능 저하.
방어: 브라우저 확장 프로그램 차단, EDR, 리소스 모니터링.
인증 공격 기법
🔨브루트포스 (Brute Force)
모든 가능한 조합을 시도해 비밀번호 추출.
온라인: 실제 서버에 요청 (느림, 탐지 용이).
오프라인: 덤프된 해시에 대해 로컬 계산 (빠름).
방어: 계정 잠금, Rate Limiting, CAPTCHA, MFA.
📖딕셔너리 / 레인보우 테이블
Dictionary Attack: 사전 단어·패턴 목록으로 시도. (rockyou.txt 등)

Rainbow Table: 사전 계산된 해시값 역조회 테이블.
방어: 강력한 솔트(Salt) 추가 → 레인보우 테이블 무효화.

# Salt 적용 예 hash = sha256(salt + password) # 같은 비밀번호도 Salt마다 다른 해시값
🔑크레덴셜 스터핑
타 서비스에서 유출된 아이디/비밀번호를 다른 사이트에 그대로 시도.

이유: 사람들이 비밀번호를 재사용하기 때문.

방어: 고유 비밀번호 정책, 유출 비밀번호 감지(HaveIBeenPwned 통합), MFA.
🎭Pass-the-Hash / Pass-the-Ticket
Pass-the-Hash: Windows 환경에서 비밀번호 대신 NTLM 해시로 인증 우회.

Pass-the-Ticket: Kerberos 티켓을 탈취해 재사용.

방어: Credential Guard, 권한 분리, 모니터링, Windows Defender.

🔐VPN (가상 사설망)
암호화된 터널로 안전하게 원격 네트워크 접속.

프로토콜:
· OpenVPN: 오픈소스, 범용적, TLS 기반
· WireGuard: 최신, 빠름, 간단한 코드베이스
· IPSec: 기업 환경 표준, 터널/전송 모드
· L2TP/IPSec: 레거시 환경

주의: VPN이 모든 것을 해결하지 않음 — 연결 후 내부 트래픽 관리 필요.
📊SIEM (보안 정보 및 이벤트 관리)
여러 소스의 로그를 수집·분석·상관관계 분석해 위협 탐지.

기능: 로그 수집·정규화, 실시간 분석, 경보, 대시보드, 보고서.

대표 제품: Splunk, IBM QRadar, Microsoft Sentinel, Elastic SIEM, Wazuh(오픈소스).

핵심 개념: Use Case 설계, 탐지 규칙(Rule) 튜닝, 위협 인텔리전스 통합.

DNS over HTTPS (DoH): HTTPS 터널로 DNS 암호화.
DNS over TLS (DoT): TLS 터널로 DNS 암호화.
RPZ (Response Policy Zone): 악성 도메인 차단.

공급업체: Cloudflare 1.1.1.1, Google 8.8.8.8, Quad9 9.9.9.9.

엔드포인트 보안
💻EDR / AV / XDR
AV (안티바이러스): 시그니처 기반 악성코드 탐지. 알려진 위협에 효과적.

EDR (Endpoint Detection & Response): 행위 기반 탐지 + 사고 대응. 알려지지 않은 위협도 탐지.

XDR: EDR + 네트워크 + 클라우드 통합 탐지.

대표 제품: CrowdStrike Falcon, SentinelOne, Microsoft Defender, Carbon Black.

· 방화벽: iptables / nftables / ufw

📱모바일 보안

위협: 악성 앱, 루팅/탈옥, 안전하지 않은 Wi-Fi, 블루투스 공격.

방어:
· 공식 앱스토어만 사용
· OS·앱 최신 업데이트
· 화면 잠금 + 생체인증
· 원격 초기화 기능 활성화

보안 아키텍처
🚫제로 트러스트 (Zero Trust)
"절대 신뢰하지 마라, 항상 검증하라 (Never Trust, Always Verify)"

핵심 원칙:
· 모든 요청을 비신뢰 네트워크에서 오는 것처럼 처리
· 최소 권한 접근
· 모든 접근을 검증·기록
· 마이크로 세그멘테이션 (Micro-segmentation)

구현 요소: MFA + Identity Provider + 기기 건강 확인 + 지속 모니터링.

참고: NIST SP 800-207 제로 트러스트 아키텍처.

🏗️DMZ 아키텍처
외부망 ↔ DMZ(웹서버, 메일서버) ↔ 내부망.

공개 서버와 내부 시스템을 분리하여 침해 시 내부망 보호.

구성: 외부 방화벽 + DMZ + 내부 방화벽.
DMZ에 두는 것: 웹서버, 메일서버, DNS, 리버스 프록시.
내부에 두는 것: DB, 파일서버, 사내 시스템.
🔬침투 테스트 (Penetration Testing)
방법론: PTES, OWASP Testing Guide, NIST SP 800-115.

단계: 사전 계약 → 정찰 → 스캐닝 → 취약점 분석 → 익스플로잇 → 후속 행동 → 보고서.

범위:
· Black Box: 내부 정보 없음 (외부 공격자 시뮬레이션)
· White Box: 모든 정보 제공 (내부 감사)
· Gray Box: 일부 정보 제공

블루팀 (Blue Team): 방어자 역할. 탐지·대응·복구 담당.

퍼플팀 (Purple Team): 레드팀 + 블루팀 협업. 공격 결과를 즉시 방어에 반영.

화이트팀: 모의 훈련 규칙·범위 관리.

🔍디지털 포렌식 기초
원칙: 원본 보존, 증거 연계 보관(Chain of Custody), 재현 가능성.

수집 순서 (휘발성 낮은 순):
CPU 캐시 → 메모리(RAM) → 스왑/페이지파일 → 네트워크 연결 → 실행 중 프로세스 → 디스크 이미지

주요 도구:
· 메모리: Volatility, WinPMem
· 디스크: FTK Imager, dd, Autopsy
· 네트워크: Wireshark, NetworkMiner
· 타임라인: Plaso/log2timeline

해시 검증: 이미지 전·후 MD5/SHA-256 일치 확인.
대칭키 암호화 (Symmetric Encryption)

암호화·복호화에 동일한 키 사용. 빠르지만 키 배송 문제가 있다.

🔐AES (Advanced Encryption Standard)
현재 표준 대칭키 암호. SPN 구조.
키 길이: 128 / 192 / 256 비트 (AES-256 권장).
블록 크기: 128 비트.
운용 모드:
· ECB: 같은 블록 = 같은 암호문 ❌ (패턴 노출)
· CBC: 이전 블록 XOR. IV 필요. 안전하지만 느림
· GCM: 인증 암호화 (AEAD). 현재 권장 ✅
· CTR: 스트림 암호화 방식. 빠름
용도: 데이터 저장, 파일 암호화, TLS 내부.
📟DES / 3DES (구형)
DES: 56비트 키 — 현재 안전하지 않음 (브루트포스 가능). ❌

3DES (Triple DES): DES를 3회 반복. 레거시 호환성용. 느리고 취약. ⚠

현재 상태: NIST 2023년 3DES 공식 폐기. AES로 마이그레이션 필요.
🌊스트림 암호 (ChaCha20)
비트/바이트 단위로 암호화. 블록 암호보다 빠른 경우가 많음.

ChaCha20-Poly1305: AEAD 스트림 암호. TLS 1.3에서 AES-GCM과 함께 사용. 저사양 기기에 유리.

RC4: 구식 스트림 암호. 심각한 취약점으로 사용 금지. ❌
🗝️키 관리
키 배송 문제: 같은 키를 안전하게 공유하는 방법이 필요.

해결책:
· 비대칭 암호로 대칭 키 교환 (TLS Handshake)
· KMS (Key Management Service): AWS KMS, HashiCorp Vault

키 보관: HSM(Hardware Security Module) — 물리적 보안 모듈.

원칙: 키를 코드에 하드코딩하지 말 것!
비대칭키 암호화 (Asymmetric / Public-Key Cryptography)

공개키(Public Key)로 암호화, 개인키(Private Key)로 복호화. 키 배송 문제 해결. 대칭키보다 느리다.

🔑RSA
소인수 분해의 어려움에 기반한 가장 널리 쓰이는 비대칭 암호.

키 길이: 최소 2048비트 (현재), 4096비트 권장.
용도: 디지털 서명, 키 교환, 인증서.

# OpenSSL RSA 키 생성 openssl genrsa -out private.pem 4096 openssl rsa -in private.pem -pubout -out public.pem
주의: 2048비트 미만 → 안전하지 않음.
〰️ECC (타원 곡선 암호)
타원 곡선의 이산 대수 문제에 기반. RSA보다 짧은 키로 동등한 보안.

비교: RSA 2048비트 ≈ ECC 256비트 보안 강도.

알고리즘: ECDSA (서명), ECDH (키 교환).
곡선: P-256 (NIST), Curve25519 (권장), secp256k1 (비트코인).

장점: 빠름, 작은 키, 모바일·IoT에 적합.
🤝Diffie-Hellman 키 교환
실제 키를 전송하지 않고 공개 채널에서 공유 비밀 생성.

동작: 각자 난수(개인값) 생성 → 공개값 교환 → 같은 공유 비밀 도출.

ECDHE: 타원 곡선 기반 DH + 임시 키 (Perfect Forward Secrecy 제공).

PFS (완전 순방향 비밀성): 세션 키가 노출되어도 과거 통신 복호화 불가.
✍️디지털 서명
목적: 무결성(변조 감지) + 인증(발신자 확인) + 부인 방지.

과정:
1. 문서 해시 계산 (SHA-256 등)
2. 개인키로 해시 서명 → 서명값
3. 수신자가 공개키로 서명 검증 + 해시 비교

알고리즘: RSA-PSS, ECDSA, EdDSA (Ed25519 권장).
해시 함수 (Hash Functions)

임의 길이 입력 → 고정 길이 출력. 단방향 함수 — 복호화 불가. 무결성 검증·비밀번호 저장에 사용.

🏛️PKI (Public Key Infrastructure)
공개키 암호화를 신뢰할 수 있게 관리하는 체계.

구성 요소:
· CA (Certificate Authority): 인증서를 발행하고 서명하는 신뢰 기관.
· RA (Registration Authority): CA 대신 신원 확인.
· CRL (Certificate Revocation List): 폐기된 인증서 목록.
· OCSP: 실시간 인증서 유효성 확인.

신뢰 체인: 루트 CA → 중간 CA → 서버 인증서.

클라이언트 → 서버
→

→
ServerHello + 인증서 + Finished
클라이언트 → 서버
→
Finished (인증서 검증 완료)
