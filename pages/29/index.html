01 데이터팩 폴더 구조
데이터팩은 세계(World) 폴더 안 datapacks/에 넣으면 자동으로 인식됩니다. 바닐라 마인크래프트에 모드 없이 커스텀 기능을 추가하는 공식 방법.
# 기본 폴더 구조 my_datapack/ ├── pack.mcmeta # 필수 - 팩 정보 ├── pack.png # 선택 - 아이콘 이미지 └── data/ ├── minecraft/ # 바닐라 오버라이드 │ └── tags/ │ └── functions/ │ ├── load.json # 세계 로드시 실행 │ └── tick.json # 매 틱(1/20초) 실행 └── mypack/ # 내 네임스페이스 ├── functions/ │ ├── main.mcfunction │ └── utils/ │ └── helper.mcfunction ├── advancements/ ├── loot_tables/ ├── predicates/ ├── recipes/ └── tags/ ├── blocks/ ├── items/ └── functions/

01 /execute — 데이터팩의 핵심 명령어
/execute는 명령어 실행 문맥(context)을 바꾸는 명령어. 하위명령을 체인처럼 연결해 복잡한 조건과 동작을 구현.
as @a
실행자(executor)를 대상으로 변경
@s 가 선택된 플레이어 각각을 가리키게 됨.
execute as @a run say 안녕 # 모든 플레이어가 각자 "안녕" 말함
at @s
실행 위치를 대상 위치로 이동
as와 함께 쓰면 각 플레이어 위치에서 명령어 실행.
execute as @a at @s run summon minecraft:lightning_bolt ~ ~ ~ # 모든 플레이어 위치에 번개 소환
if block ~ ~-1 ~ stone
특정 좌표의 블럭 조건 확인
execute as @a at @s if block ~ ~-1 ~ minecraft:stone run say 돌 위에 서 있음 # 플레이어 발 아래 블럭이 돌인 경우만
if entity @s[tag=vip]
엔티티 존재/조건 확인
execute if entity @a[tag=vip] run say VIP 플레이어 있음
if score @s kills matches 10..
스코어보드 값 조건 확인
execute as @a if score @s kills matches 10.. run function mypack:reward # 킬 10 이상인 플레이어에게 보상
unless
if 의 반대 조건
execute unless entity @a[gamemode=creative] run say 서바이벌 플레이어만 있음
positioned 0 64 0
실행 위치를 절대 좌표로 이동
execute positioned 100 64 200 if block ~ ~ ~ minecraft:chest run say 해당 좌표에 상자 있음
store result score @s obj
명령어 결과를 스코어보드에 저장
execute store result score @s health run data get entity @s Health 1 # 플레이어 체력값을 health 오브젝트에 저장
in minecraft:the_nether
특정 차원으로 실행 위치 이동
overworld · the_nether · the_end 선택 가능.
rotated as @s
실행 회전을 대상의 바라보는 방향으로 설정
execute as @a at @s rotated as @s run summon minecraft:arrow ^ ^ ^3 # 플레이어가 바라보는 방향 앞 3블럭에 화살 소환
02 /scoreboard — 변수 시스템
Scoreboard는 데이터팩에서 변수 역할. 플레이어·엔티티별 정수값을 저장·연산.
scoreboard objectives add kills playerKillCount
오브젝트(변수군) 생성
criterion: dummy(수동) · playerKillCount · deathCount · health · xp · level · food · air
scoreboard players set @s kills 0
값 설정 (절대값)
scoreboard players set @s kills 0 scoreboard players add @s kills 1 # +1 scoreboard players remove @s kills 1 # -1 scoreboard players reset @s kills # 초기화
scoreboard players operation
스코어 간 연산
# target obj 연산자 source obj scoreboard players operation @s total += @s bonus # 연산자: += -= *= /= %= = < > <> # < 는 최솟값, > 는 최댓값, <> 는 swap
scoreboard objectives setdisplay sidebar
사이드바/탭/벨로우네임 표시
sidebar · list · belowName 위치 선택.
scoreboard objectives setdisplay sidebar kills

🎯 선택자 & 조건
@a · @p · @e · @r · @s · 선택자 인수 · Predicate JSON
01 기본 선택자
@a
모든 플레이어
All players — 온라인 플레이어 전체.
@p
가장 가까운 플레이어
Nearest Player — 실행 위치 기준 최근접 1명.
@e
모든 엔티티 (플레이어 포함)
All Entities — type 인수로 좁히는 게 일반적.
@r
랜덤 플레이어 1명
Random player. limit 인수로 n명 선택 가능.
@s
명령어 실행자 자신
execute as 로 바뀐 실행자 = @s.
02 선택자 인수 [...]
[type=zombie]
엔티티 타입 필터
@e[type=minecraft:zombie] @e[type=!minecraft:player] # 플레이어 제외
[distance=..10]
거리 필터
..10 = 10 이하 · 5.. = 5 이상 · 3..8 = 3~8블럭
@a[distance=..5] # 반경 5 내 플레이어
[limit=1,sort=nearest]
수 제한 · 정렬
sort: nearest · furthest · random · arbitrary
[tag=vip]
태그 필터
tag=!vip 로 태그 없는 엔티티 선택.
[scores={kills=5..}]
스코어 기반 필터
@a[scores={kills=10..,deaths=..3}] # 킬 10 이상이고 사망 3 이하인 플레이어
[gamemode=survival]
게임모드 필터
[name="플레이어명"]
이름 필터
name=!"이름" 으로 특정 이름 제외.
[nbt={OnGround:1b}]
NBT 조건 필터
@e[type=zombie,nbt={IsBaby:1b}] # 아기 좀비만 선택
[predicate=mypack:cond]
Predicate JSON 조건 적용
복잡한 조건을 JSON 파일로 분리. 아래 참고.
[x=0,y=64,z=0,dx=10,dy=5,dz=10]
특정 박스 영역 내 필터
x/y/z 시작점, dx/dy/dz 크기(+방향으로만).
03 Predicate — 복합 조건 JSON
Predicate는 data/mypack/predicates/ 폴더에 JSON으로 작성. 복잡한 조건을 재사용 가능한 파일로 분리.
data/mypack/predicates/is_raining.json
{ "condition": "minecraft:weather_check", "raining": true } # 사용: execute if predicate mypack:is_raining
data/mypack/predicates/full_hp.json
{ "condition": "minecraft:entity_properties", "entity": "this", "predicate": { "type": "minecraft:player", "nbt": "{Health:20.0f}" } }
자주 쓰는 condition 종류
entity_properties
엔티티 속성 검사 (type, nbt, location 등)
entity_scores
스코어보드 값 범위 확인
location_check
위치·바이옴·구조물·빛 레벨 확인
random_chance
확률 기반 조건 (0.0~1.0)
all_of / any_of / inverted
AND / OR / NOT 논리 결합
🔮 인첸트 전체 목록
모든 인첸트 · 적용 가능 아이템 · 최대 레벨 · 상호 배타 관계 · NBT 명령어 적용법
▶ NBT로 인첸트 적용 — 레벨 제한 없음
데이터팩에서 인첸트 적용: /enchant 명령어는 최대 레벨만 허용되지만, /give 의 NBT로는 레벨 32767까지 지정 가능.
# 일반 인첸트 적용 (/enchant — 최대 레벨 준수) enchant @s minecraft:sharpness 5 # NBT로 레벨 제한 무시 (/give) give @s minecraft:diamond_sword{ Enchantments:[ {id:"minecraft:sharpness",lvl:32767s}, {id:"minecraft:unbreaking",lvl:10s} ] } # 1.20.5+ 컴포넌트 방식 give @s minecraft:diamond_sword[ minecraft:enchantments={ "minecraft:sharpness":5, "minecraft:unbreaking":3 } ] # 상호 배타 인첸트도 NBT로 강제 적용 가능 give @s minecraft:diamond_sword{ Enchantments:[ {id:"minecraft:sharpness",lvl:5s}, {id:"minecraft:smite",lvl:5s} ] }

05 🆕 새로운 블럭 만들기 — 6가지 방법
바닐라 마인크래프트에는 진짜 새 블럭 ID를 추가하는 것이 불가능합니다. 그러나 아래 방법으로 완전히 다른 텍스처·모델을 가진 블럭처럼 보이는 것은 만들 수 있습니다.
방법 1 — 커스텀 플레이어 헤드 (가장 쉽고 대중적)
# 텍스처 Base64 값은 minecraft-heads.com 또는 namemc.com 에서 획득 give @s minecraft:player_head{ SkullOwner:{ Properties:{ textures:[{ Value:"eyJ0ZXh0dXJlcyI6eyJTS0lOIjp7InVybCI6Imh0dHA6Ly90ZXh0dXJlcy5taW5lY3JhZnQubmV0L3RleHR1cmUvNjE3NzdiMjc..." }] } }, display:{Name:'{"text":"커스텀 블럭","italic":false}'} } # 블럭으로 설치: 마인크래프트 헤드는 벽·바닥에 직접 설치 가능 # 단점: 위쪽 면 텍스처만 표시, 회전 제한됨, 전면부 텍스처 불일치
방법 2 — 버섯 블럭 + 리소스팩 텍스처 교체 (6면 독립 텍스처)
# brown_mushroom_block은 6면 각각을 on/off 제어 가능 # 전부 false로 설정 → 갈색 반투명 블럭(무독립 텍스처) setblock ~ ~ ~ minecraft:brown_mushroom_block[ up=false,down=false,north=false, south=false,east=false,west=false ] # 리소스팩 assets/minecraft/textures/block/brown_mushroom_block.png # 를 원하는 텍스처로 교체 → 게임 내 모든 버섯 블럭이 바뀜 # 더 정교하게: note_block, mushroom_stem 등도 활용 가능
방법 3 — Item Display 엔티티 + custom_model_data (1.19.4+, 가장 강력)
# 실제 블럭 없이 어떤 모양이든 공중에 렌더링 summon minecraft:item_display ~ ~ ~{ item:{ id:"minecraft:stick", count:1, tag:{CustomModelData:1001} # 리소스팩에서 정의한 모델 번호 }, item_display:"fixed", # ground·fixed·head·gui·thirdperson_lefthand 등 transformation:{ translation:[0f,0f,0f], scale:[1f,1f,1f], left_rotation:[0f,0f,0f,1f], right_rotation:[0f,0f,0f,1f] }, brightness:{block:15,sky:15} # 항상 밝게 렌더링 } # 리소스팩에서 stick의 override에 custom_model_data:1001 → 커스텀 블럭 모양 모델 연결
방법 4 — Block Display 엔티티 (실제 블럭 모델 그대로 렌더링)
# 실제 블럭을 설치하지 않고 블럭 모양 렌더링 (히트박스 없음) summon minecraft:block_display ~ ~ ~{ block_state:{ Name:"minecraft:diamond_block" }, transformation:{ translation:[0f,0f,0f], scale:[0.5f,0.5f,0.5f], # 0.5배 크기 left_rotation:[0f,0.3827f,0f,0.9239f], # 45도 Y 회전 right_rotation:[0f,0f,0f,1f] }, brightness:{block:15,sky:15}, glow_color_override:-1 }
방법 5 — 보이지 않는 아이템 액자 + 커스텀 모델 아이템
# 아이템 액자를 보이지 않게 만들고 커스텀 아이템 넣기 # 리소스팩에서 item_frame.json 모델을 투명으로 교체 summon minecraft:item_frame ~ ~ ~{ Invisible:1b, Fixed:1b, Item:{ id:"minecraft:stick", Count:1b, tag:{CustomModelData:1001} } } # 바닥·벽·천장에 부착 가능. 단점: 액자가 붙은 방향만 가능
방법 6 — 장벽 블럭 + 아이템 디스플레이 (히트박스 있는 커스텀 블럭)
# 장벽(barrier)으로 충돌 히트박스 만들고, 그 위에 item_display로 외관 setblock ~ ~ ~ minecraft:barrier summon minecraft:item_display ~ ~ ~{ item:{id:"minecraft:stick",count:1,tag:{CustomModelData:1001}}, item_display:"fixed", Tags:["custom_block"] } # 히트박스 있음 + 커스텀 외관 = 가장 블럭다운 느낌 # 단점: 마이닝 이벤트 감지(advancement로)해서 수동 처리 필요
06 🎮 크리에이티브 인벤토리에 커스텀 아이템 추가하기
바닐라에서는 크리에이티브 탭에 새 칸을 추가할 수 없습니다. 단, 아래 방법으로 커스텀 아이템을 게임 내에서 쉽게 꺼낼 수 있습니다.
방법 A — /give 명령어로 직접 지급 (핫바·채팅 활용)
# .mcfunction 파일에 등록하고 커맨드 블럭 또는 채팅으로 호출 give @s minecraft:stick{CustomModelData:1001, display:{Name:'{"text":"마법 지팡이","color":"light_purple","italic":false}'} } # 또는 함수로 묶어서 function mypack:items/magic_wand
방법 B — 지식 책(knowledge_book)으로 클릭 지급 UI 만들기
# 지식 책은 크리에이티브 인벤에 있고, 클릭 시 레시피 언락 가능 # 활용: 독자적인 "아이템 책" UI — tellraw + clickEvent 조합 tellraw @a [ {"text":"[클릭] "}, {"text":"⚔ 전설의 검 받기","color":"gold","underlined":true, "clickEvent":{"action":"run_command","value":"/function mypack:items/legendary_sword"}}, {"text":" "}, {"text":"🪄 마법 지팡이 받기","color":"light_purple","underlined":true, "clickEvent":{"action":"run_command","value":"/function mypack:items/magic_wand"}} ]
방법 C — 크리에이티브 탭 '검색'에서 찾기 (크리에이티브 모드 한정)
# 1.20.5+ 컴포넌트 방식 아이템은 검색창에 아이템명으로 찾기 불가 # 단, 기본 아이템(stick, diamond_sword 등)은 검색 탭에 있음 # 크리에이티브 탭 추가: 바닐라로는 완전히 불가 → 모드(CraftTweaker, FTB Quests) 필요 # 서버에서는 커맨드 블럭 패널 or 커스텀 GUI로 대체
방법 D — 커스텀 상점 NPC (서버 맵에서 가장 실용적)
# Interaction 엔티티(1.19.4+)로 클릭 감지 → 아이템 지급 summon minecraft:interaction 10 64 10{ width:1f,height:2f,response:1b, Tags:["shop_npc"] } # advancement로 우클릭 감지 → 상점 메뉴 함수 실행 # data/mypack/advancements/detect_click.json { "criteria": { "click": { "trigger": "minecraft:player_interacted_with_entity", "conditions": { "entity": {"nbt": "{Tags:[\"shop_npc\"]}"} } } }, "rewards": {"function": "mypack:shop/open"} }

Storage (1.15+)는 플레이어/엔티티와 무관하게 임의 NBT 데이터를 저장하는 전역 공간.
# storage에 값 저장 data modify storage mypack:global GamePhase set value "active" data modify storage mypack:global BossHP set value 500 # storage에서 값 읽기 data get storage mypack:global GamePhase data get storage mypack:global BossHP # storage → scoreboard 로 복사 execute store result score global boss_hp run data get storage mypack:global BossHP # 조건 분기에 활용 execute if data storage mypack:global {GamePhase:"active"} run function mypack:game_loop

# setup.mcfunction 에서 상수 설정 scoreboard objectives add const dummy scoreboard players set #2 const 2 scoreboard players set #100 const 100 scoreboard players set #1000 const 1000 # 활용: 점수를 100으로 나누기 (백분율) scoreboard players operation @s percent = @s score scoreboard players operation @s percent *= #100 const scoreboard players operation @s percent /= global max_score # 전역 카운터 (# 접두사 = 가짜플레이어 관례) scoreboard players add #total kills_total 1 scoreboard players get #total kills_total
